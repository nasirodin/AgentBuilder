| Q12 | Holdout set: generated by the architect or by a separate, isolated agent? | Separate agent reduces leakage. | Separate agent, stored outside workspace. |

| Q15 | Resource limits on Linux: require `systemd-run --user` cgroups or settle for rlimits? | cgroups give real memory/pids caps; not available in every WSL2 distro setup. | cgroups when available, rlimits fallback, reported by `doctor`. |
| Q16 | Is process-level isolation (shared kernel, same uid) sufficient long-term? | Fine for a single-user dev tool; weaker than container/microVM. | Yes for v1; keep protocol open for a stronger backend. |
| Q17 | seccomp: hand-assembled BPF via ctypes vs. a libseccomp binding? | Hand-written: no deps, tiny filter, but per-arch syscall tables to maintain. Binding: robust, but a C library dependency. | Hand-written (x86-64, aarch64). |
| Q18 | Write the HTTP/SOCKS proxies ourselves or use an existing asyncio library? | Own: full control over filtering, IP vetting, decision events; few hundred lines. Library: less code, harder to hook decisions. | Own. |
| Q19 | Should the bridge rely on `socat` (like srt) instead of our Python bridge? | socat: battle-tested, extra system dep. Python bridge: needs the host interpreter visible in the sandbox (already true). | Python bridge. |
| Q20 | Block private ranges (RFC1918/ULA) in resolved-address vetting by default? | Blocks LAN/intranet exfiltration; breaks agents meant to hit internal APIs. | Block by default; per-domain opt-out via approval. |
| Q21 | Two drafts from the same base version: second release must rebase, or becomes a branch-off? | Linear versions are simpler to reason about; branches allow experiments. | Linear: second release requires rebase onto latest (re-run regression gate). |
| Q22 | Version scheme: monotonic integers vs. semver? | Integers are simple; semver could signal interface-breaking changes (inputs/output schema). | Integers + automatic "interface changed" flag computed from manifest diff. |
| Q23 | Can a target agent call other registry agents as tools (composition)? | Powerful, but nested sandboxes, cost accounting and versions pinning get complex. | Not in v1; design manifest `interface` so it is possible later. |
| Q24 | Secret injection: env var visible to agent code vs. proxy-side injection with TLS interception? | Env var is simple, relies on allowlist to limit exfiltration; proxy injection keeps the value out of the sandbox but needs a MITM CA. | Env var + domain-gating for v1. |
